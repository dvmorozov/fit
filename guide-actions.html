minimize-difference

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Fit the current model to the profile.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/minimize-difference.

It builds one fit task for each fit interval, finding the intervals first where fewer than two bounds are marked, and fits the model's curves to the data in each, minimising the objective chosen for the session with the engine chosen for it. When the chosen engine cannot run here, the built-in one does and the reply says so. It ends with the model it reached, which the next run carries on from.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It does not choose the model: curve positions, background points and fit intervals are set beforehand, and a request the session's state cannot meet is refused with the reason.

minimize-difference-again

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Continue fitting from where the last fit stopped.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/minimize-difference-again.

It fits again over the tasks the last run built, starting from the model that run, or a Stop, left rather than from the seeds.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It needs a model ready to fit: before one exists, or while data is missing, it is refused with the reason.

minimize-number-of-curves

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Fit, then drop curves that do not earn their place.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/minimize-number-of-curves.

It fits the model, then removes every curve the fit can do without, by the rule chosen for removing curves, fitting again as it goes. When no fit interval or curve position exists yet it computes them first. The fit intervals already marked are kept.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It is refused, with the reason, for a curve type placed from a pack's own markup when that type cannot be reduced curve by curve.

do-all-automatically

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Background, positions and fit, in one pass.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/do-all-automatically.

It chooses the fit intervals and the background itself, places the curves, fits and reduces them interval by interval, and fits the curves that remain at full precision.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It replaces the fit intervals and background points that were marked; only the curve positions picked by hand are kept. Use minimize-number-of-curves to keep the intervals.

smooth-profile

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Smooth the experimental profile.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/smooth-profile.

Each amplitude becomes the mean of itself and its two neighbours, rescaled so the total of all amplitudes is unchanged: the area is kept and the highest peaks come down a little.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It changes the data that will be fitted, and cannot be undone except by loading the profile again.

compute-curve-bounds

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Work out where each curve begins and ends.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/compute-curve-bounds.

It proposes the fit intervals for the profile: the stretches that each become one fit task.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • A model whose module proposes no intervals is refused with the reason rather than searched for peaks it is not made of.

compute-background-points

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Propose background points from the profile.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/compute-background-points.

It marks the points of the profile it takes to lie on the background, to be subtracted through (subtract-background).

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It proposes points; it does not fit or subtract the background. It is refused while a background curve is the model's background: a model has a curve or selected points, never both.

compute-curve-positions

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Propose a curve position for each peak found.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/compute-curve-positions.

It replaces the curve positions with ones found in the data, at the local maxima (or minima, as the curve type asks) that stand above the background fraction of the highest point. A curve type placed from its own markup is placed by its pack instead.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It is refused with the reason when the curve type cannot be placed this way.

select-all-points-as-curve-positions

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Use every profile point as a curve position.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/select-all-points-as-curve-positions.

It puts a curve position at every point of the profile, or of the data interval in force, as the starting point from which minimize-number-of-curves removes the curves not needed.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • A curve type placed from its own markup refuses it, because a pattern per point is not a count of anything.

select-entire-profile

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Fit over the whole profile rather than a marked interval.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/select-entire-profile.

It lifts a selected data interval, so the whole profile is in force again. When it already is, the reply says so.

It is registered as asynchronous: a caller does not wait for a result but polls the problem's async state for its progress and end.

Limitations

  • It concerns the data interval, not the fit intervals.

create-curve-list

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Rebuild the curve list from the current model.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/create-curve-list.

It collects every curve's parameters from the model as it stands, for the curve list to be read.

It is done when the reply comes.

Limitations

  • It is refused until a fit has produced a result to collect from.

evaluate-model

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Measure the model as it stands, without fitting it.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/evaluate-model.

Every interval reports the R-factor of what it holds and no value moves. It is how a model put back by value, such as a reopened project, is measured without a fit.

It is done when the reply comes.

Limitations

  • It is refused while a calculation runs, since measuring a model that a fit is moving would report neither the old nor the new; with no model there is nothing to measure.

stop

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Stop the operation now, keeping what it has reached.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/stop.

It asks every running task to stop. A stop is not a cancel: what the operation reached is the model, unfinished but complete, and the next run starts from it.

It is done when the reply comes.

Limitations

  • It stops the operation that is running, not later ones.

subtract-background

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Subtract the background from the profile.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/subtract-background.

It subtracts a piecewise-linear background through the background points from the profile, or from the data interval in force. With auto set in the body, or with fewer than two points marked, it proposes the points itself. The background points are cleared afterwards.

It is done when the reply comes.

Limitations

  • It rewrites the profile that will be fitted, and is refused before anything changes when the build has no background arithmetic, or while a background curve is the model's background.

select-profile-interval

This software's choice — A decision made by this software rather than by the field's sources; the explanation says why it was made.

Restrict the fit to the interval between start and stop.

A verb of the compute server's action route, run by POSTing to /problems/{id}/actions/select-profile-interval.

The body gives the start and stop point indices of the data interval in force.

It is done when the reply comes.

Limitations

  • It needs start and stop in the body, and is refused with the reason when the interval cannot be taken.
